## 第三档 · 决定告警好不好用

### 7. 什么算「失败」？（断言口径）

```
[ ] 响应 code != 200 才算失败
[ ] 返回体的字段结构不对也算失败（比如该有的字段没了）
[ ] 响应时间超过 ______ 秒也算失败
[ ] 返回的数据条数为 0 算失败
[ ] 其他：____________________________________
```

### 8. 哪些「红」是正常的 ← **这个比想象中重要**

测试环境总有些已知问题，比如：某接口只在生产才有数据、某个服务测试环境根本没部署、某个账号没开通权限。

不把这些列出来，每天的推送里就会混着一堆「永远红但没人管」的用例 —— 这叫**告警疲劳**，一周之后群里就没人看消息了，你的推送也就白做了。

```
已知的、可接受的失败：
- ____________________________________
- ____________________________________
- ____________________________________
```

### 9. 通知策略

```
[ ] 每天一条「全绿」日报，失败时也发
[ ] 只有出现失败才推，全绿就静默
[ ] 全绿和失败都发，但失败才 @ 人

连续失败几次需要升级提醒（说明可能是环境问题而不是业务问题）：______ 次

需要保留多长时间的执行历史（用来画趋势）：______
```

## 关于密钥：**请不要贴在对话里**

建议按这个流程给我：

1. 我先在项目里生成两个文件：
   - `conf/config.local.yaml` —— 真实配置，我同时把它写进 `.gitignore`
   - `conf/config.example.yaml` —— 占位符版本，可以进仓库给同事看
2. **你自己**往 `config.local.yaml` 里填账号密码和 webhook
3. 你跟我说一句「填好了」，我读本地文件

这样全程不经过聊天记录。以后就算仓库公开、或者聊天记录被别人看到，密钥也不会泄露。
